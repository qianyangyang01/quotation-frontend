# 固定采购表格接续导入

## 使用规则

采购 Excel 直接上传原文件，后台仅解析表格数据，不导入 Excel 内嵌图片或图片列。浏览器不再解压、移除图片或重新打包；原文件不会被改写。建议以后使用不含图片的表格：含图片的原文件仍会按完整大小上传。新导入任务按固定文件名、工作表名称和 Excel 实际行号识别来源，不要求每行都有 SKU。

保持文件名和工作表名称不变，日常在末尾追加数据。例如旧表成功导入至第31行，追加后再次上传，将跳过已处理的旧行，仅让新增行进入待确认入库。旧商品不会被删除或再次覆盖。

同一文件、工作表和实际行号对应同一个商品。首次没有 SKU 也可入库；以后在该行补上正式 SKU，重新上传时给原商品补编号，不创建另一份商品，不覆盖已维护的图片、价格、备注等资料。再次上传相同 SKU 应跳过，不重复改版本；旧稿仍为空 SKU 时也不能清掉系统已经补好的编号。

仅允许空 SKU 补全，不通过接续导入修改已有正式 SKU。如果目标 SKU 已属于其他商品，或系统中的原商品已有不同正式 SKU，则阻止该次续传并说明冲突。只补编号不代表缺失的成本、重量等资料已完整，商品能否报价仍依照现有完整性和停用规则判断。

系统按每一行的真实入库结果判断，不只记最大行号。若第20行失败而第31行已成功，修正第20行后仍可补导。过去明确选择忽略的重复 SKU 行不应当作普通错误行重新导入。

待确认任务不会推进成功记录。部分失败任务中已经成功提交的行也会被识别。回滚只处理对应批次实际写入的商品；回滚成功后，这些行不再算已经入库。

## 安全限制

- 同一来源的旧行业务字段变更（允许的空 SKU 补全除外）、缺失、移动，或历史记录存在歧义时，停止自动接续并说明工作表及行号，不自动改为全量覆盖。
- 新尾行使用该来源已处理的 SKU 时，需要明确处理重复问题，不借接续导入静默覆盖旧商品。
- 固定表格接续不负责更新历史行的价格、图片或其他资料。系统中后来手工修改的旧商品应保留原状。
- 更换文件名会被当作不同来源，不应通过改名规避旧行冲突。文件名和工作表名应稳定且具有业务辨识度。
- 行号身份依赖表格位置稳定；内容完全相同的无SKU行相互交换，系统无法仅凭内容识别。因此不能将变更检查当作允许随意排序或挪动旧行的保障。
- 旧版本历史记录只保留已识别的业务字段，首次接续只能核对这些字段及其位置。新任务额外记录已识别字段的原始文本指纹；均不能证明未识别列、被忽略重复列或原始公式表达式从未变化。
- 为检查旧行是否变化，后台仍需读取工作簿中的表格数据。接续主要减少重复入库，不代表不读取或不上传旧行。
- 无 SKU 行继续使用临时编号，接续不会重复生成同一历史行的商品；临时编号的商品仍遵守现有不可报价规则。

## 验证计划

| 场景 | 必须满足的结果 |
|---|---|
| 混合有SKU/无SKU，首次导入至31行，再追加32行 | 旧行不写入、只导入32行；原商品数量和版本无额外变化 |
| 原表不变反复上传，连续三个批次 | 明确无需入库；多批历史累计不漏行 |
| 第20行错误、后续行成功，修正20并追加32 | 只补导20和32，不能把错误洞跳过 |
| 空SKU旧行补正式SKU | 只更新原商品编号，产品ID、图片、人工维护资料保留 |
| 补SKU后再次上传同表，或又上传空SKU旧稿 | 不新增、不重写版本、不清除已经存在的正式SKU |
| 补SKU撞号、系统已有不同正式SKU | 阻止接续，不覆盖另一商品、不擅改正式SKU |
| 补填非法或超过96字符的SKU | 原值保留、该行标错；不能截断后入库，也不能导致整批暂存崩溃 |
| 旧行改价、清空业务字段、插入、删除、重排 | 阻止接续，指出冲突位置，不产生商品写入 |
| 工作表改名或被删除；仅调整工作表顺序 | 前者阻止；后者保持同名工作表历史识别 |
| 历史用户选择跳过一条重复SKU行 | 再次上传不能自动把未选行覆盖回商品 |
| 追加行SKU已在该来源历史中 | 明确冲突，不静默覆盖 |
| 老版本成功历史，包含AUTO临时编号 | 兼容识别旧行；矛盾历史保守阻断 |
| 两个同来源任务同时待确认、执行 | 确认和写入前重查；无SKU行不会生成两份商品 |
| 部分批次提交后失败、重试 | 已提交行不重写，未提交行可继续 |
| 后续批次回滚、重新导入 | 不动前批旧商品，回滚行可重新入库 |
| 仅补SKU批次回滚 | 恢复补号前状态，不删除原商品，不改图片关系；有后续修改时拒绝回滚 |
| 旧商品已手工补图片、改价、停用或改SKU | 重传旧表仍跳过该行，保留人工维护结果 |
| 旧版待确认任务与旧任务详情 | 不伪装成接续模式，保留既有操作行为 |

生产验收应与本地测试分开记录，不使用生产写入来模拟上述案例。
