# 燕文化妆品快递更新复用现有渠道

“燕文化妆品快递（到门）”已有公司渠道绑定，但最初的手工建档使用 `YW-COSMETICS-1224`。完整原表导入按公司 ID 生成 `C-…` 编码，原流程仅按生成编码查找，因此试图另建一条渠道，在绑定时触发 `(dataset_id, company_channel_id)` 唯一约束。

导入现在优先解析同一物流库中的已登记绑定，再核对生成编码。复用现有渠道 ID、规则 ID、内部编码和财务键，不迁移、不重建渠道。绑定与生成编码指向不同渠道、物流商不一致或生成编码已绑定其他公司渠道时明确阻断，保留原绑定。未登记渠道仍沿用原有生成编码逻辑。原有数据库锁、草稿基线校验、审核发布与幂等处理继续生效。

生产程序只改动 `LogisticsImportService`，不改解析器和计费规则，不做数据库迁移。公司目录里的“化妆品”属性、名称中的“到门”及原财务授权保持原值。

`LogisticsImportBindingPostgresTest` 在隔离 PostgreSQL 中覆盖：

- 已绑定手工编码的正式版本接收原表、生成待审稿并审核发布；重复原表不新建版本；再次改价复用渠道。
- ID、编码、规则 ID、财务配置、其他渠道及历史报价快照保持稳定。
- 不同物流商、不同公司绑定和生成编码冲突明确拒绝，不覆盖绑定。
- 可通过 `YANWEN_BINDING_SOURCE` 指定用户原始工作簿，验证完整 14 行真实渠道导入；CI 使用可重现的最小原表结构夹具。

上线后仅重新导入本次失败渠道，生成待审稿；其他 12 条渠道已有待审稿不重导、不发布，历史正式运价继续有效。原错误批次保留为历史记录，新导入批次提供恢复后的核价入口。
