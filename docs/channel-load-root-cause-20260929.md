## 已在当前生产版直接复现的根因

使用现有 QIANYANGYANG 会话，打开精确 release=-01 页面，不保存业务数据：

1. 未查询商品，打开常用国家，搜索并点以色列，出现与用户截图相同的“渠道加载失败，请重试”；反复点重新加载不恢复。
2. 此时 ensureCountries 只允许 ready/empty，初始 idle 直接返回 false；上次修复只覆盖 error/stale，不包含 idle。没有真实国家请求失败也会显示网络错误。
3. 再查询 BK2601961，物流实际加载成功，以色列明确显示5条渠道，但局部 countryError 仍存在，v-if 持续隐藏渠道列表。后台成功和界面失败形成矛盾。
4. 切换商品/物流属性使旧国家请求的 generation 失效时，同样可能回传 false；迟到的旧结果也会写入局部错误。

## 修改

- 未查询商品或待重新查询的撤回草稿，明确提示先查询商品，保留已选国家供后续商品查询使用，不进行缺少商品成本的试算。
- 商品已具备条件而物流处于 idle 时，国家入口启动初始化；沿用已有 error/stale 恢复与并发共享。
- 国家仅在已核验 ready/empty 状态标记 channelsLoaded；缓存 stale 不当成成功。
- 常用国家组件以已核验父级国家状态为准，清除旧错误并忽略迟到的旧失败；加载中不同时显示历史错误。指定国家/模板选择器同步修复提示与恢复。
- 保留真实错误信息与服务端可用请求编号；真实失败保留重新加载按钮。
- conditionalGet 增加30秒网络及响应体读取期限，正常取消与超时区分，完成后清理定时器；不自动重放报价提交、不使用未确认物流版本放行保存。
- 不修改计价、权限、物流数据、数据库或已保存报价。
