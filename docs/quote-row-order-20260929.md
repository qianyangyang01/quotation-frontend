# 保存平均报价行顺序

平均报价行原来只在组件内记录移动位置；保存再打开后，平均行会追加到来源行末尾。现在客户报价与首次报价单快照保存 `rowOrder`，使用 `option:<保存渠道ID>` 和 `average:<方案ID>` 区分两种行，重新打开、预览、报价图片及“仅复制报价单”恢复同一顺序。

新报价保存和记录内保存都传递顺序；单独改客户价格保留已有顺序。旧客户端未传此字段时后端保留原值，旧客户端删除平均方案时清除该方案的失效顺序引用。显式非法、重复或外部行标识会被拒绝。旧记录没有顺序字段时沿用原有布局，不猜测或回填过去未保存的位置。

这是展示快照变更，无数据库迁移，不改变系统价、客户价、平均计算、首次报价单或审核确认状态。完整对账复制继续保留原有费用明细和单独的平均方案附录。

验证覆盖：实际组件移动后保存重开、图片渲染顺序与表格复制、记录改价保存保留顺序、真实新建保存函数的标识转换、HTTP 新建/PATCH/GET 读回、旧客户端兼容、非法标识拒绝、价格与确认状态不变。本地浏览器使用合成数据复现及验收，不创建生产测试报价。

发布必须包含前后端。回退旧后端后继续编辑新记录可能丢失顺序字段；需要回退时优先评估写入兼容性，禁止通过重算历史报价修复布局。
