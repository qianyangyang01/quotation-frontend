# 物流业务验收与必用渠道门槛

## 范围与边界

实施基线：`3943398e61a3c5a3ba019e6f3836a30c5ef3b7db`，独立工作区 `quotation-logistics-rebuild`。
本阶段只修改物流价格、计费验收、报价物流提交校验及相关测试。采购、培训和其他财务业务逻辑不变。
生产代码发布、生产准备区写入和生产整库切换均未执行，必须分别确认。

原表和已交付标准模板不修改。88 个解析分组不是 88 个已经验收的下单产品；极通两个分组仍有多产品语义待核验。
真实日常必用清单没有默认值，必须由业务用户选择。合成 QA 清单不能替代真实用户确认。

## 状态与持久化

- `logistics_required_revision`：数据集内递增修订号、渠道 UUID、确认状态、备注、操作者、时间；追加保存历史，不覆盖旧修订。
- `logistics_billing_acceptance`：价格版本 UUID、价格行指纹、计费实现版本、独立预期样本、服务端计算结果、审核人和时间。
- `logistics_version_quote_ready`：服务端根据已发布价格和有效验收记录计算；Excel 和客户端的 `quoteReady` 不能授权报价。
- 指纹包括整份价格行 JSON。新版本即使价格相同也不继承旧验收；计费实现版本必须精确一致。
- V26 仅为迁移前原库的已发布版本保存兼容记录，保持准备期间旧报价可用。兼容记录不是新库计费验收，不能授权新导入的版本。

计费实现升级时，必须同时升级 Java `LogisticsBillingEngine.VERSION` 及新数据库迁移中的资格函数实现版本。不得仅修改常量或静默替换算法。

## 服务端计费边界

当前引擎仅接受明确的 CNY 公斤价、首续重或区间固定价；支持每票费、固定附加费、公斤价最低计费重量，以及系数明确的体积重。
禁止未知规则默认放行：分区邮编、发货区域、计费进位、燃油、干线、尺寸限制、特殊收寄及未结构化原文继续阻断。
同一输入匹配多个价格也阻断，不选最低价。

完整版本验收至少要求每一档两个不同重量的独立预期运费，以及越界或准入拒绝样本。样本必须附原表位置/核算依据；这些是最低接口门槛，不替代业务人员核对完整收寄规则。
后续渠道适配还需补齐该渠道边界、尺寸、货物属性和分区场景，不能仅提交两条样本就宣称真实业务验收完成。

报价提交使用当前数据集和规则修订，检查渠道 UUID、价格版本 UUID、有效计费记录及财务允许范围。服务端按提交的重量/尺寸输入重新计算物流费，费用不符或旧页面版本过期时要求重新计价。不会重新计算或修改历史报价金额。

## 新接口

统一前缀 `/api/v1/logistics/rebuild`，沿用物流权限与认证。

| 接口 | 用途 |
| --- | --- |
| GET/PUT `/datasets/{id}/required-channels` | 查询/修订必用清单，写入要求 revision、备注和幂等键 |
| GET/POST `/versions/{id}/billing-acceptance` | 查询/提交当前已发布版本的计费验收，写入要求指纹、实现版本、人工样本和幂等键 |
| GET `/imports/{id}/files/{index}/evidence` | 下载该原文件逐单元格解析证据，鉴权并记录审计 |

原有切换预览新增必用清单版本、确认状态、数量、未通过明细和 requiredReady。
切换事务再次校验清单、预览、备份及映射；仅有一个可报价渠道不足以切换。
无法匹配的财务引用不放宽，模板/草稿保留明确处理状态。

## 真实模板性能缺陷修复

浏览器实际导入完整 12.7 MB 模板时，首轮处理 199103 ms，其中解析 7861 ms、入库 191241 ms。
根因是每创建一个渠道都将约 26.5 MB 原表单元格证据重新写入批次进度，且查询返回相同大字段。
修复为原始证据单独保存到报价系统对象存储，批次只保留摘要、证据键和 SHA256；价格行仍保留原始值和来源。
新旧批次兼容，旧记录不删除、不批量改写；保留原文件下载。

最终同一模板复测：上传 715 ms、解析 11156 ms、入库 11928 ms，后端总处理 23084 ms；88 分组、3094 行、0 解析阻断、0 自动报价渠道。进度响应约 32 KB，完整证据约 63.7 MB 单独保存并校验 SHA256。首次必用清单查询 5345 ms，仍有进一步查询优化空间。该结果是本机单次验收，不是生产并发 SLA。

开发服务增加忽略后端构建目录与输出目录，避免 Maven/Jacoco 产物触发前端不断刷新或 Windows 文件锁导致开发服务退出。

## 自动化与业务核验方式

1. 前端类型检查、lint、Vitest、构建及隔离检查。
2. PostgreSQL/Testcontainers 覆盖 V25→V26 迁移、原库兼容、必用清单版本冲突、完整版本样本要求、费用篡改、旧版本拒绝、失效验收、备份/预览及事务切换。
3. 原表回归：11 文件/61 工作表；重量增行、档位拆分、表头移动、合并区域和字体颜色；三处业务确认修正、澳洲分区、试算与重派费用分离。
4. `scripts/qa-logistics-rebuild.mjs`：固定本地 QA 地址和专用身份保护，真实原表导入、审核、分页导出、原件哈希、重新导入、并发幂等、合成切换和回滚。
5. `scripts/qa-logistics-template.mjs`：真实标准模板往返、3094 行业务数据、证据哈希、性能报告、未预选的完整勾选清单。

测试输出在 `backend/target/logistics-api-qa/`、`backend/target/logistics-template-qa/`、`backend/target/logistics-corpus/`；不提交原表、账号密码或会话数据。
WSL 的 Mockito 测试需要显式加载本地 Byte Buddy agent，保留 JaCoCo agent；不能以跳过 PostgreSQL 测试代替通过。

## 2026-08-31 登录后浏览器追加验收

用户在 Codex 内置浏览器自行登录本地隔离环境 `127.0.0.1:5519`，身份为本地 QA 管理员；未读取会话凭据。以下结果来自真实按钮、文件选择器、下载事件和下载后文件检查，不用 API 通过代替浏览器通过。

### 发现并修复的问题

1. 原先 `fetch → Blob URL → 点击链接` 在内置浏览器中无报错但不下载，15 秒内无下载事件且磁盘无文件。静态 HTTP 模板下载正常。改为后端鉴权生成原生 HTTP 下载链接，页面明确提示点击保存；准备和实际下载均保留权限与审计，未引入匿名公开链接。当前价格链接带版本/筛选快照校验，价格变化后拒绝旧链接并要求重新生成，实际导出在固定数据库快照内完成。改变筛选、页签或数据集时清除旧下载提示。
2. 对相同业务价格重导入时，页面正确显示“价格未变”，但批次差异表错误复用历史版本首次导入的“新增 44 条”。现按本批结果生成 0 新增、44 未变，完整原值等于新值；历史版本自身的首次新增差异保持不变。变化明细补充分区列。批次处理完成不再一律显示待审核，文件失败与渠道阻断仍明确提示。

## 尚未满足的生产门槛

- 用户尚未确认真实日常必用渠道。
- 全部真实渠道尚未取得完整计费验收；已能管理价格不等于可安全报价。
- 必用渠道确定后，逐个补充原表独立最终运费样本和实际登录报价提交验收。
- 生产备份、实际关联影响确认、发布和切换尚未执行；本地合成切换成功不代表生产验收。
- 整库切换成功且发生新业务后，不做自动整库覆盖恢复，使用受控版本回滚与关联复核。
