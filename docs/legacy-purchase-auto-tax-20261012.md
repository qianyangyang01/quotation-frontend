# 旧采购资料：未税单价与票点自动生成含票价

## 用户操作

- 仅对“2026旧数据”调整编辑器：第14项为未税采购单价，第23项含票价只读，第24项票点可编辑。
- 用户输入单价或票点时，立即预览“未税单价 ×（1＋票点）”，按十进制四舍五入保留两位小数。
- 例如未税价100、票点0.1，含票价为110；仅将票点改为0.08，含票价变为108。
- 缺失可靠未税价格时留空并提示确认，不用含票价反推或冒充未税价。改价格或票点必须补齐两个输入。
- 仅查看、取消或修改备注等无关字段时，保留既有价格。历史报价快照不修改。
- 0票点的含票价等于未税价；原有报价1%加成仍是独立规则，编辑器明确提示。

## 数据与兼容

为避免改变列表、分析和已有采购消费者的有效价语义，保留旧数据存储契约：

| 字段 | 含义 |
| --- | --- |
| sourceQuotedPriceCny | 编辑器显示并维护的未税采购单价，修改写入审计 |
| taxPoint | 采购票点，0必须显式填写 |
| taxIncludedPriceCny | 自动生成的含票单价 |
| purchasePriceCny | 兼容现有消费者的有效含票单价，与上述结果一致 |
| purchasePriceBasis | tax_included |
| legacyPriceMode | auto_tax，表示用户已明确维护过自动计价输入 |

后端忽略自动计价提交中的旧含票值，用未税单价与票点重新计算；版本冲突仍拒绝保存。
已启用自动计价的记录，旧客户端丢失模式标记时拒绝静默退回旧规则，要求刷新页面。
正常资料编辑和模板确认使用同一个准备函数。模式标记随API归一化保存，重新打开仍展示未税价。
自动计价基准档不再按原始价与含票价“是否相等”猜测税率；可选阶梯档仍按该档未税价加当前票点一次。

采购粘贴/石墨的稀疏更新对已启用自动计价的记录沿用相同规则：采购单价映射为未税价，票点变化重新计算，仅修改含票价会提示改源输入。
未启用自动计价的导入/同步记录保留既有兼容规则，不批量迁移或重算。

## 验证范围

- 前端：输入改价、仅改票点、保存后列表/重新打开一致、含票框只读、缺失原价、非法/空票点、只改备注。
- 计算：基准价不重复加税、阶梯价、0票点独立加成、十进制舍入、未修改对象保持不变。
- 后端：服务重算、旧含票值覆盖防护、版本冲突、旧客户端保护、非法输入、审计未税价/票点/计算方式。
- PostgreSQL/API：编辑保存与回读、修改记录、粘贴预览/确认/幂等/仅改票点、无关字段保存、过期版本拒绝。
- 本改动没有数据库迁移，也没有批量写入生产采购或历史报价。
