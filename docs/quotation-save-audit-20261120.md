# 报价保存专项排查与修复

## 已确认的问题

组合 SKU 编辑框中的 `SKU1+SKU2*2`、分号分隔文本、尚未输入完整的末尾加号，会被后台版本轮询作为单一 SKU 请求，触发 422「SKU格式不合法」。两天内确认 13 次，发生于用户编辑过程。后台轮询现在仅使用符合 SKU 格式的完整输入；不猜测、拆分或改写用户输入。保存前仍传递全部活动 SKU，继续严格检查采购、财务和所选物流版本。

仅修改前端后台轮询。价格算法、报价保存接口、数据库结构及历史报价保持原业务规则。
