# 2026 新版石墨采购自动同步

## 修改前基线与回退

2026-09-27 从线上 current、manifest 和容器核实：`quotation-2026.09.27-01`，Git `9a7bf9eac47f4ca8adbae3084078c4c6a387f663`。本次回退目标是这个版本，非当时 previous 指向的 `quotation-2026.09.24-18`。前后端及解析器镜像均为 `quotation-2026.09.27-01`。发布前还必须重新核实基线，避免覆盖期间的其他发布。

应用版本回退不能自动撤销已同步的采购资料。先暂停任务；通过同步变化表预览需撤销的记录，只撤销产品 ID 和版本仍匹配的变更，跳过后续人工维护。同步新建的商品回退为停用，保留引用和审计；已有商品恢复修改前完整采购资料。历史报价不重算。禁止用整库恢复覆盖期间正常业务。

## 范围

固定文件 `m4kMMD8Vm2hdrPkD`（国际站2026询价新版）。当前已逐页实测的 13 个 sheet：

`张汝玉Raul,张汝玉Calin女装,张汝玉Fem女装,乔月,陈晨,陈晨BK,陈晨枕头,刘玉宏,孙丽红,陶春燕,汪晶,业务新人,老数据更新`

“国际站”“国际站批发报价”在读取器中强制排除，即使误填到配置也不会读取。新增或改名 sheet 需要更新经过核实的配置名单，不能根据未知名字猜测来源。D–AI 列文字字段与采购粘贴列一一对应，A–C 图片不读取、不覆盖。

同 SKU 在“老数据更新”出现时，它覆盖其他 sheet 的来源优先级，即便自身尚未补齐也不回退采用其他页旧值。“老数据更新”自身重复 SKU，或其他 sheet 间出现重复且没有优先来源，均进入待处理。只有“老数据更新”允许更新系统 `legacy_2026` 来源，继续使用原价格归一化和粘贴校验，不擅自把旧记录转换成新记录。

## 时间与业务规则

- 独立单线程后台任务启动后 30 秒首次检查，每轮结束后等待配置的间隔（默认 600 秒，即 10 分钟）；多实例通过 PostgreSQL 会话 advisory lock 保证不重叠。外部读取期间不持有采购行锁或长事务。
- 普通轮次处理新 SKU 和之前校验未通过、现在已补齐的 SKU。已有成功同步商品的修改记为“等待中午更新”。
- 普通轮次只读取表头、SKU 索引，以及新增/待补齐 SKU 所在的 150 行批次，跳过不含待处理 SKU 的批次；不为检查已知正常商品而拉取全部文字字段。已有商品的首次完整比对在中午轮次或管理员显式完整同步时执行。
- 北京时间每天 12:30（含）至 13:00（不含）的调度检查中，执行一次完整更新；失败可在该窗口内断点重试。完整检查已成功的日期不会重复执行。窗口内启动的轮次可完成到窗口之后；不是在整段时间持续写入。服务整个窗口停机则当日已有商品更新跳过，需管理员完整同步或等待次日。
- 完整更新比较整行，复用 `PurchasePasteService.preview/confirm` 的字段白名单、稀疏合并、校验、版本保护及保存；空白保留，明确 0 / 0% 是有效值。
- 自动同步额外要求石墨原行必须具备正克重和有效票点，即使系统旧值齐全也不能替代源表缺失字段。其他字段按粘贴合并后的规则校验。校验失败只影响该 SKU，继续处理其他合格商品。
- 默认关闭。管理员可启用、暂停或立即完整同步，采购可查看同一份状态、待处理与变更记录。立即完整同步会在中午窗口外也更新已有商品，属于显式管理员操作。
- 最近同步后产品版本或 ID 已发生变化，记为冲突，防止覆盖后续人工维护。删除源行不会删除系统商品。回退过的商品不会再次被自动覆盖。

## 断点续读

读取顺序为：表头校验 → 当前 SKU 索引 → 每批最多 150 行 × 32 列。每张表先读取 G2:G5001 的索引；达到 5000 条返回行时明确停止，禁止静默截断。

每个成功批次落在 `shimo_sync_fetch_page`；每张表索引摘要落在 `shimo_sync_fetch_sheet`；任务保存 sheet 与下一批行位置。接口失败或进程重启，后续轮次复用成功批次，仅请求失败及尚未读取的批次。恢复前重新校验表头和 SKU 索引：插行、删除、排序导致摘要变化则废弃该 sheet 的缓存，其余 sheet 不受影响。超过 30 分钟的暂存页重读，避免长时间故障后采用陈旧暂存资料。

整轮保存完成后删除本轮临时读取页，只保留任务状态、待处理清单和正式同步前后快照，避免每 10 分钟永久存放一份全表副本。

所有配置 sheet 读取成功、每行 SKU 与索引一致后才进入采购写入阶段。写入逐 SKU 事务提交，采购数据、采购历史、同步变更前后快照和成功状态同事务保存。重试已保存内容不会再次写入或生成重复历史。读取过程中石墨继续改动时不保证跨 sheet 的原子快照，后续轮次会继续比较。

## 配置与观察

仅后端配置下列变量，解析器不启用同步。授权凭证仅放服务器受限的 `deploy/.env`，不进入仓库、前端、报告或请求日志。

```dotenv
QUOTATION_SHIMO_WORKER_ENABLED=true
QUOTATION_SHIMO_INTERVAL_SECONDS=600
QUOTATION_SHIMO_TOKEN=<server-only-secret>
QUOTATION_SHIMO_SHEETS=张汝玉Raul,张汝玉Calin女装,张汝玉Fem女装,乔月,陈晨,陈晨BK,陈晨枕头,刘玉宏,孙丽红,陶春燕,汪晶,业务新人,老数据更新
```

数据库 `shimo_sync_control.enabled` 初始为 false。连接配置和数据库开关均需开启才自动执行。暂停时正在读取的一次 HTTP 请求可能继续结束，但保存阶段逐条检查开关；暂停返回后不会再启动新的采购写入。

采购资料维护页新增折叠的“石墨新版自动同步”：只在打开时读取状态，每 15 秒刷新。展示范围、阶段、读取位置、失败原因、待补齐清单、所有字段前后变化，可筛选克重变化。无新查询报价路径上的石墨请求。

接口：GET `/api/v1/purchase-shimo-sync`、`/items`、`/changes`；超级管理员 POST `/enabled`、`/run`。服务端账号 `shimo-sync` 记录自动修改，操作名“石墨自动同步”，不伪装采购本人。

## 回退操作

1. 超管暂停 `/enabled`，确认后台不再写入。
2. 需要撤销采购数据时，按任务 ID 调用 `/runs/{id}/rollback-preview`，检查可撤销与后续修改冲突清单；再调用 `/runs/{id}/rollback`。均需现有登录、CSRF 和超管权限。跨多个连续同步批次的同 SKU 不能机械逆序恢复：每次恢复会产生新版本，需按审计核对，接口会拒绝版本不匹配。
3. 核对变更和历史报价保持不变，保留备份与证据。
4. 使用部署回退脚本切回核实的旧版前后端镜像。V54 为新增表迁移，保留其审计数据，不删除 Flyway 历史，不执行全库回滚。
