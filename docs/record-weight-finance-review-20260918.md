# 报价记录重量与财务审核

- 对账复制按数量档输出最终含包材重量（g），读取保存的 weightSnapshot、logisticsSamples 或明确数量的 logisticsInput。旧记录没有依据时显示未保存，不用当前包材规则反算。
- 财务审核与成交状态、报价确认独立，pending / approved / rejected；绿色可报价，红色价格有误，均不限制复制。记录审核人、时间及修改历史。
- 超级管理员与财务角色还须具有 allRecords 权限才可审核。员工只读本人记录；通用修改接口仍仅能修改自己的记录，不能伪造审核字段。
- 审核使用独立 PATCH /quotations/{id}/finance-review 与 _version，JPA 乐观锁保证并发只有一项成功。修改客户报价的数量或价格后清除审核结果；普通备注不清除。
- 列表及打开的详情每次完成查询后 3 秒检查审核状态，恢复前台和网络立即查询。仅请求当前页与打开记录，最多 100 个 ID。后台标签页暂停；账号变化和页面销毁取消请求；失败明确提示并重试。
- 实时审核徽标与编辑中的记录版本分离，避免后台同步把未保存编辑覆盖或掩盖版本冲突。复制对账时重新读取服务端记录，确保复制当前已保存的完整信息。
- 审核筛选同时刷新列表，原有成交汇总保持原口径。历史记录缺失审核字段时视为待审核，不做批量写入。
- 无数据库迁移，不改采购、财务、物流或历史价格；主目录的未提交修改保留。

验证覆盖：管理员/财务审核员工记录、员工越权/跨账号读取隔离、非法字段、旧版本冲突、8 个审核写入并发、改价与审核并发、改价重置/备注保留、前端 3 秒同步/失败恢复/乱序与账号切换、拒绝状态可复制、历史重量缺失与新包材一次性重量。
