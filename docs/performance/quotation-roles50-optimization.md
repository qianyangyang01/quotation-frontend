# 50人采购、报价与物流性能优化

## 范围与实现

从生产 quotation-2026.09.05-17 / d8816b923b17d8b0ffaf3a63bfe39ff2a10c6dca 建立独立工作区。
修改采购查询、采购页面请求生命周期和物流读取；不新增接口或迁移，不改变价格计算、税费、角色授权及生产业务数据。

- 采购非空搜索：去掉通用SQL中的空词分支，将匹配ID与更新时间物化一次，同时生成精确总数和当前页；只读取当前页的商品JSON。空搜索直接分页，精确SKU保持原路径，中文、大小写、通配符和原JSON搜索覆盖范围保持兼容。
- 短关键词执行计划：非空宽泛搜索的只读事务内使用 `set_config('plan_cache_mode','force_custom_plan',true)`，使数据库按当前关键词选择计划。设置仅限当前事务，集成测试验证事务结束后恢复原值；不修改数据库全局配置。
- 采购统计：三个独立聚合合并为一次；搜索、翻页不重读全局统计。首次进入、保存/导入变化时刷新，页面可见时每分钟更新统计。
- 采购交互：新条件立即使旧请求失效并取消；列表不再等待统计接口。保存首页无筛选商品时使用服务器返回值更新列表，保留权威版本、成本、报价资格；筛选或后续页仍重新查询。防止重复点击保存。
- 同一组件中相同页面的在途请求合并，数据写入强制刷新；并发删除使当前页越界时自动查询最后一页。搜索防抖250ms不等于接口延迟，不能宣称每次输入100ms内获得远端结果。
- 物流读取：活动数据集查询改为每条SQL一次的标量子查询，减少逐行函数调用；目录复用有界版本缓存，并合并同版本冷加载。每次仍核验实时版本，停用/归档/规则/验收变化使缓存失效；不使用固定TTL跳过实时版本核验。

## 风险与回归

搜索重点检查列表与总数一致、最后页/超出范围页、中文与SKU、JSON任意字段、空词和SQL通配符；使用真实PostgreSQL和旧查询逐项对照。搜索结果不缓存价格。
前端测试覆盖旧搜索晚返回、请求取消、统计失败不阻塞列表、保存使用服务器返回且不重复列表读取、重复点击保存。
物流测试覆盖规则资格、国家/渠道过滤、目录缓存后停用失效、旧revision拒绝。权限异常测试复用独立50并发夹具。

## 复现约束

所有负载脚本只接受 http://127.0.0.1:端口。禁止改为生产URL。
使用 quotation_perf 匿名测试库，50个独立测试会话：20业务、28采购、2物流。每次操作后250ms思考时间；保留原来查询与保存比例。
脚本位于 scripts/performance/roles50：accounts-load.mjs、monitor.mjs、accounts-abnormal.mjs、purchase-import.mjs、logistics-import.mjs、search-probe.mjs。
环境变量 PERF_BASE_URL、PERF_USERS=50、PERF_ROLE_MIX=true、PERF_WARMUP_SECONDS=30、PERF_DURATION_SECONDS、PERF_OUTPUT；测试密码来自独立夹具或PERF_PASSWORD，不能使用生产账号。

本地同一数据快照恢复后ANALYZE，后端2CPU/1GiB，PostgreSQL1.5CPU/512MiB，Redis0.25CPU/160MiB，连接池10。旧版及第一版优化各做5分钟同资源对照。额外短词搜索探针发现执行计划问题，修复后再验证；最终30分钟测试将PostgreSQL固定为2CPU/512MiB，其余预算不变，必须单独列示资源因素。
最终持续测试期间另加一次1000行采购导入和一次停用渠道的物流标准Excel导入/审核；这些是额外会话，不混入主50会话操作百分位。后期再用一个额外只读会话测中文短词搜索。不是50个浏览器，也不是50人同时上传大文件。
快照恢复的生成列依赖public中的SQL函数；恢复SQL需要将pg_dump默认空search_path改为public。此修正仅作用于隔离数据库恢复脚本，不修改迁移或生产配置。

性能门槛：查询p95<500ms/p99<1s，保存p95<1s/p99<2s，错误率<0.1%。接口耗时与界面输入耗时必须区分，浏览器功能验收不能冒充前端p95测试。
