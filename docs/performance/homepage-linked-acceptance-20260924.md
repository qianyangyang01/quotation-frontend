## 修复及边界

- 登录不再等待财务设置；认证、路由权限、报价就绪及保存版本保护保持生效。
- 首页采购从 48 页完整资料改为一次 SKU、品类、采购价投影；报价统计在同一 repeatable-read 数据库快照内读取完整记录清单，避免并发新增引起分页重复或漏计。两接口均受公司统计权限保护。读取不完整时禁止统计和导出并提供重试。
- 物流版本列表先分页再展开历史价格 JSON，避免分页前反复处理大型历史数据。
- 真实已有渠道上传发现 JPA 草稿尚未 flush 就被 JDBC 读取，已修复事务内可见性；真实 XLSX 名称不匹配但表内渠道名匹配的新建和更新均通过。
- 并发小文件撞上独立解析器容量时，仅对无副作用解析的 429 限次退避重试；格式错误直接保留失败。
- 采购短词搜索不再每次转换全库 JSON。内存只复用 PostgreSQL 规范化后的搜索文本；每次在 repeatable-read 快照中校验全部行 ID、SKU、版本和时间，增量刷新变更、移除已删行。返回的商品和价格重新从同一数据库快照读取；SQL 通配符仍保留原路径。
- 集成另一任务的审核版本一致性、共享只读审核状态、旧草稿缺少 product 时的恢复修复。专项证据另见 `purchase-review-deep-stress-20260923.md`。
- 50 人预检发现公司列表反复展开历史国家和处理标记造成 P95 约 2 秒。索引仅复用每条记录的国家及 `quoteConfirmed` 提取结果；每次重新读取当前账号与生命周期范围及行版本，不缓存授权范围、金额或完整记录，保持数据库排序。国家变更、转移归属、归档/回收、删除、处理标记及交叉筛选均与原 SQL 对账。
- 持续写入压测发现报价统计仍随新增历史 JSON 增大而变慢，30 分钟阶段 P95 达 2,153.50ms，未通过性能门槛。增加仅供统计使用的精简投影缓存，每次读取完整 ID、版本、更新时间和生命周期范围，仅重建变更行；在同一数据库快照内取值，删除/回收立即移出，返回防御性副本，上限 50,000 条。报价计算和保存不使用这个统计缓存。回归覆盖版本更新、仅时间戳更新、并发事务快照、回收/恢复、删除和响应对象隔离。

- 固定 Chrome/headless、1440×1000、本机回环网络、每次独立浏览器上下文，20 次点击登录到统计加载完整可筛选导出：同一 462 条报价数据快照下，基线 P95 6,133.60ms，候选 P95 1,807.30ms，下降 70.5%。第一次候选计时全部通过，之后角色导航因测试选择器假设物流默认页签而中断；该问题已修正。最终五角色及超时/离线重试完整浏览器回归通过，P95 1,803.04ms（隔离数据新增后）。此数值不是公网耗时承诺。

- 五角色页面路由、菜单范围、退出切换账号、无权限误报检查通过；首页请求超时及断网注入后不显示虚假统计、禁用导出，恢复后重试与实际 CSV 下载通过。
- 真实 HTTP：全量新旧数据逐字段对账、单品及组合报价保存读回、多人抢审及旧版本拒绝、员工与管理员同条记录一致、财务更新使旧报价失效且历史金额不变、采购维护实时可见及历史、草稿与模板归属、归档回收恢复与首页联动通过。
