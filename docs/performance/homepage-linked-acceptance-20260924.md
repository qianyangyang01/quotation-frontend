## 修复及边界

- 登录不再等待财务设置；认证、路由权限、报价就绪及保存版本保护保持生效。
- 首页采购从 48 页完整资料改为一次 SKU、品类、采购价投影；报价统计也使用单语句完整快照，避免并发新增引起分页重复或漏计。两接口均受公司统计权限保护。读取不完整时禁止统计和导出并提供重试。
- 物流版本列表先分页再展开历史价格 JSON，避免分页前反复处理大型历史数据。
- 真实已有渠道上传发现 JPA 草稿尚未 flush 就被 JDBC 读取，已修复事务内可见性；真实 XLSX 名称不匹配但表内渠道名匹配的新建和更新均通过。
- 并发小文件撞上独立解析器容量时，仅对无副作用解析的 429 限次退避重试；格式错误直接保留失败。
- 采购短词搜索不再每次转换全库 JSON。内存只复用 PostgreSQL 规范化后的搜索文本；每次在 repeatable-read 快照中校验全部行 ID、SKU、版本和时间，增量刷新变更、移除已删行。返回的商品和价格重新从同一数据库快照读取；SQL 通配符仍保留原路径。
- 集成另一任务的审核版本一致性、共享只读审核状态、旧草稿缺少 product 时的恢复修复。专项证据另见 `purchase-review-deep-stress-20260923.md`。
- 50 人预检发现公司列表国家选项展开历史报价造成 P95 约 2 秒。新增只复用国家提取结果的索引；每次重新读取当前账号与生命周期范围及行版本，不缓存授权范围，保持数据库排序。国家变更、转移归属、归档/回收、删除和空集均与原 SQL 对账。
