# 顺丰原价与操作费列的识别修复

## 问题与规则

2026-10-17 导入的《顺丰国际电商产品价格表(20261019）.xlsx》中，“敏货电商专递”H、L 两列表头都是“专递操作费/票”。旧解析器只保留最后一个同名表头，导致 L57:L61 为空时忽略 H 列已经明确填写的费用：波兰 H57:H58 为 15 元，奥地利 H59:H61 为 23 元。

用户明确指出 L 列是操作费。原表另有 9 行 H、L 金额不同，不能把左侧原价操作费覆盖到右侧有效操作费。修复按下列范围处理：

- 仅对顺丰、恰好两列同名费用，以及明确的“原运费 / 原操作费 / 重量 / 折扣 / 折后运费 / 操作费”列顺序使用成组规则。
- 右侧操作费是有效非负数字时采用右侧，保留明确的零值，不再乘运费折扣。
- 右侧是真空白，且该行折扣、折后运费都是真空白、现有运费规则已经选定原价时，读取左侧明确的原价操作费。
- 右侧已填写但无效、公式错误、折扣计价行缺失右侧操作费、左右都缺失时继续阻断。禁止将失败当作有效零费。
- 其他重复费用布局仍要求含义、有效数字一致；冲突不自动选取。其他物流商的选列规则不变。
- 保存候选单元格、原值、表头、空白状态、最终采用的单元格和选择依据。

Excel 流式读取器原来会丢弃公式文本，使带数值缓存的外部引用绕过既有数值解析器的外部引用检查。现将显式外部引用公式保留为错误值，避免当作空白回退，或把其缓存直接视为可靠费用。不会执行公式或访问外部文件。
