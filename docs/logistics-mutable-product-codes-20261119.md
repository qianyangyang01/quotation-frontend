# 物流价表产品代码更新识别

问题：部分原表适配器把初次接入时的产品代码作为必需值，或把目录旧代码写回解析结果。同一产品更新代码后，可能被误拦截、漏导或保留错误的来源代码。

本次按用户要求，继续帆之润的按价格区块识别方式，检查现有原表解析器及公司渠道匹配。以同一物流商下的完整渠道名称、登记别名和明确货物属性识别产品；原产品代码是辅助证据，正常换码不要求修改代码白名单。读取和保留当次原表代码，缺少代码时不伪造目录代码。

| 范围 | 修正 |
| --- | --- |
| 百州 | 精确服装渠道标题匹配，移除 BZ503 唯一值要求，保存实际代码 |
| 云途、燕文、万邦 | 移除旧代码相等门槛，按名称对应既有计费、重量和必需列规则 |
| 捷易通达 | 名称明确时允许更新产品 ID；已知 1961/2001 的不同服务冲突仍拦截 |
| 极通环球 | 定制纯电按名称识别，读取新代码；带标签及独立代码单元格不限定 JT 前缀 |
| 巧捷 | 精确产品名称后缀、独立代码标签及价格行代码均读取实际值；美国范围和整票计费按产品名称保留 |
| 容鼎 | 名称或登记别名明确时支持更新基础代码；同格 A/C 数量、顺序、标签与名称对应检查保留 |
| 急速国际 | 美国敏感货通过明确货物属性识别更新代码，继续排除普货和其他国家；最低计费重量规则随渠道保留 |
| 顺友 | 按标题读取实际产品代码，不再用目录固定代码填充原表来源 |
| 帆之润 | 保留前版动态区块识别，本次继续回归 |

通用匹配继续检查已知代码与名称是否分别指向不同渠道；代码单独命中但名称表达不同货物属性时禁止误归属。明确属性列与渠道名称、登记属性存在冲突时阻断。多重身份、价格缺列、重量错误、容鼎 A/C 错位等实际问题继续阻断；不对未知名称做模糊自动替换。

保留的历史产品代码用于已知冲突检查、兼容识别和按名称取得的计费规则索引，均不是新代码白名单。没有修改公司渠道目录或历史代码登记，也没有批量重算报价。

线上复核发现容鼎当前原表名称已变化，目录仍保留旧名且未登记别名。因此导入快照还会只读取得当前启用物流库、当前已发布版本、有效公司绑定对应的成功匹配记录，把已确认的原始名称作为 `importAliases`。它不改写目录，排除草稿、旧库、其他文件、其他渠道及被过滤的匹配。以后来源名称由已发布证据维护，不在代码里固定一组容鼎名称替换规则。

验证覆盖跨物流商换码后的公司渠道 ID、行数、公斤价、单票费、重量段、起重、计费模式、进位及允许属性；包括巧捷、极通和急速真实原表的换码前后逐行对比。另保留旧代码冲突、属性冲突及容鼎 A/C 错位的反例。巧捷可选真实源测试的重量边界期望同步为现行 1g 进位参数；整票 B 的原表未标注代码，来源代码应为空而不是目录常量。计费引擎没有改动。

发布仅更新后端及解析服务。解析版本 `mutable-product-identities-2026.11.19-v24`，兼容已审核的 v23 草稿；不导入新价格，不改已发布运价、历史报价、审核状态、财务设置和其他系统。完整 CI、原表探针、发布和数据回读证据保存于对应本地发布包。
