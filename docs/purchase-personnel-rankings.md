# 采购人员排名

采购资料维护新增默认收起的排名入口。每组统计范围和时间条件首次展开时读取一次，此后在当前页面保留结果，仅点击“刷新统计”或“重试”才重新读取。采购页定时统计、资料保存、收起再展开都不触发重载；收起期间已有请求可以完成，同条件不重复请求，离开页面时取消未完成请求。手动更新保留当前表格，失败保留上次结果；不同条件的结果独立保存，晚到响应不会串入当前条件。统计说明集中在独立的默认收起区域。

## 统计口径

- 全部采购：统计当前权限允许、且可唯一关联到采购角色账号的普通采购及 FOB 资料，不提供来源下拉。接口权限沿用采购目录权限。
- 在售 SKU：复用已配置销量文件的主 SKU 清单，精确匹配，不推断子 SKU。未匹配单列，不算个人缺失。
- 补全率：按当前采购报价人归属，已完整 SKU / 总 SKU。同一 SKU 跨来源仅计一次，各份资料均完整才算完整；归属不一致或未填写人员不计入排名和汇总，不分配给某个采购人。
- 普通采购完整条件：正式 SKU、正重量/起订量、有效采购价、明确票点、已知 1 件运费或明确包邮。旧资料价格须大于 0。FOB 检查重量原文、已解析的起订量、价格、运费。此口径与可报价资格独立，不改变报价资格。
- 异常：只读取正式完成的采购价格异常事件，覆盖普通/组合、FOB 单条与逐项、批量单品审核。忽略领取、取消、修正和未处理行的重复快照。
- 时间：近 7/30/90 天为到请求时刻的滚动窗口，全部时间自历史开始。按审核事件时间，不按报价创建时间。缺时间的异常报价单列，不推断日期。
- 去重：同一报价 ID + SKU 在所选时间内计一项；采用区间内首次采购异常事件保存的采购归属，后续资料归属修改不覆盖历史归属。多 SKU 同一报价可以多项。
- 关联报价数：所选时间内完成过审核、关联该采购人的去重报价数；异常报价采用事件归属，非异常采用当前资料归属。异常占比使用异常报价数 / 关联报价数，不是异常项数 / 关联报价数，不代表责任认定。
- 历史未分类、缺时间提示也只统计可关联采购账号的记录。未归属异常不计入，不推断采购责任。销量未匹配数仍用于说明销量文件与采购目录的匹配情况，不作为个人排名数据。导出使用页面当前排序、并列名次和汇总口径，并保护文本单元格免于公式执行。

## 账号与排序

- 只按 `app_user.role_key = purchase` 判断参与资格；管理员或具有采购页面权限的其他角色不计入。停用但仍为采购角色的账号保留统计，避免把停用登录等同于删除历史。
- 账号（忽略大小写）和全名精确匹配。已由业务确认的简称绑定到固定账号：黄→HUANGCHUANZHEN、支→ZHIXINYU、周→ZHOUYUANYUAN、章→ZHANGPANPAN、杨→YANGJIAOJIAO、樊→FANDONGLING、谢→XIEGANG、郑→ZHENGKE、方→FANGRENJUAN、唐→TANGHUIZHEN、刘→LIUSIYUAN。其余简称不猜测。角色变化后这些映射也必须重新通过角色校验。
- 同一账号的简称、全名和账号合并；多来源 SKU 在合并后判定归属冲突。重名或别名冲突不自动分配；能通过唯一账号识别的重名人员显示姓名与账号。
- 默认显示“已完整数量排名”，可切换“完整度排名”。数量榜先比已完整数量，再比原始补全率；完整度榜顺序相反。使用未四舍五入的比例排序，两项相同按竞赛名次并列，名称仅稳定展示顺序。切换只处理已读取快照，不发请求。
- 取消人员最高/最低提示。汇总显示当前资料范围内采购人数、名下 SKU、已完整、待补全及整体补全率；整体比例用总数计算，不平均个人百分比。异常榜可能包含只有历史异常、当前没有资料的采购账号，其人不计入资料汇总人数。
- 已完整数量表示当前资料存量，不代表本月补全工作量。没有新增月度贡献统计。
- 影响面限定排名接口、排名组件、CSV 与相应测试。账号管理、采购列表、报价计算、权限及数据库结构不变。角色改变后，已打开排名在下一次手动刷新时反映。

## 安全与验证

`GET /api/v1/purchase-rankings` 使用只读一致性事务，只投影必要资料字段和审核事件。无数据库迁移，不回写采购资料、历史报价、审核状态或金额。

单元测试覆盖去重、多人/多 SKU、历史人员归属、分类、未知日期、销量范围、零值及来源合并。PostgreSQL 集成测试执行真实 SQL、普通/FOB/批量审核投影、权限和读取前后指纹比较。组件测试覆盖首次展开、无定时刷新、重复展开复用、同条件请求合并、手动刷新保留结果、失败重试、筛选缓存和响应隔离。发布和线上验收证据按版本保存在本地 release-packages。
