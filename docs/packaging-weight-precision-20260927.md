# 小数克重报价保存修复

FL2600257 的采购克重为 39.7g。二进制浮点除以 1000 得到
`0.039700000000000006`，前端序列化含包材重量为
`0.04070000000000001`，与后端 BigDecimal 结果
`0.040700000000000006` 不完全相同，导致保存返回包材快照不一致。

- 采购数据前端映射和后端导入派生公斤值使用十进制换算。
- 后端重量校验允许最多 `1e-12 kg`（十亿分之一克）序列化尾差；
  非法数、负数、数量及包材规则校验继续保留，实际重量差异仍拒绝。
- 校验仅比较，不修改提交快照；无数据迁移、批量重算或历史报价更新。
- 已有采购数据在前端按原始克重读取，不需要修改生产采购资料。

回归覆盖 39.7g 单品的 1/2/3/7 件、组合 SKU、整票特殊包装、旧浮点值
保存校验、实际重量偏差拒绝，以及报价 API 保存、幂等重复提交、回读和
先前报价不变。API 本地测试使用测试库并模拟物流/资料就绪依赖；生产
物流有效性由原有校验和完整 CI 回归继续验证。

修复前新增前端用例 2 项失败、后端用例 2 项失败；修复后前端专项
62 项通过、后端专项 17 项通过。发布前另需精确提交完整 CI 和生产技术核验。
