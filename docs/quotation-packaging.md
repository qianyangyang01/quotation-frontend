# 报价包材重量

- 普通包材按每个实物商品计算：`ceil(单件基础重量g / 50) × 1g`。不足50g向上取整，基础重量为0时普通包材为0。
- 单品：`(单件基础重量 + 单件普通包材) × 件数 + 特殊包装重量`。
- 组合：`sum((各SKU单件基础重量 + 单件普通包材) × 单套件数) × 套数 + 特殊包装重量`。
- 特殊包装按整票只增加一次，不乘件数或套数，不参与普通包材的计算。留空表示0；接受0～100000的整数克。
- 示例：140g商品普通包材为3g，特殊包装10g时，1件153g、2件296g、5件725g。

## 联动和权限

单品、组合共用当前报价的特殊包装输入。改值后重新计算国家/渠道矩阵、最低价、选中方案、全部数量档位、预览及复制价格；物流起重和按重量税费继续采用原有各自计算规则。非法输入保留原文、显示错误，并拦截有效报价计算、复制和保存。

员工与管理员沿用`quote`权限。`specialPackagingGrams`随账号草稿保存，缺失的旧草稿按0处理；清空新建恢复为空。草稿仍通过版本号控制并发修改，不跨账号共享特殊包装输入。

## 保存和追溯

新正式记录保存`weightSnapshot`：规则版本`per-item-50g-1g-v1`、整票特殊包装克重、每个SKU的数量/基础重量/普通包材，以及所有报价数量档位的重量拆分。

各渠道`logisticsInput`保存商品重量、普通包材、特殊包装、总包材、整票重量及对应数量；`logisticsSamples`保留原有运费复核用途。后端以BigDecimal复算快照，并核对各渠道的物流输入，拒绝重复叠加或不一致的重量。

内部记录详情和对账复制展示保存的重量依据。客户报价图片仍只显示最终价格。后续编辑客户报价不能修改重量快照。

旧正式记录没有新快照时，保留原价格和重量，明确显示未保存完整包材依据，不按新规则推算。没有数据库迁移、历史批量更新或采购资料改写。旧客户端缺失新快照仍兼容，发布后须刷新正在打开的报价页面以使用新规则。
