# 再次发起报价与全部国家渠道搜索

本次仅修改报价前端及前端渠道目录读取方式，不修改数据库、正式价格或原报价记录。

## 使用行为

- 报价记录行新增“再次发起”，有报价权限时显示。通过报价详情 API 读取完整原记录后进入“我的报价”。
- 带入客户、客户等级、客户操作费选择、单品或组合 SKU、组合数量、自定义数量、物流属性、渠道和区域身份、模板信息、佣金阈值和特殊包装克重；采购价格、重量及物流费用按当前资料计算。成交结果、审核确认、原单身份和手工客户报价不会作为新单结果复制。
- 已有服务器草稿时，先选择保留或载入原报价。自动保存继续使用服务器草稿版本号，沿用并发冲突保护。采购读取失败时不替换现有表单。
- 原渠道失效时保留无价格的提示行，允许移除；不会按同名渠道套用价格。保存正式报价仍沿用现有新建及校验流程。
- 常用国家区域默认显示常用国家；输入国家名称、代码、物流商、渠道名称或代码，可查找非常用国家及授权渠道。选中国家后按需加载运价。清空搜索保留已选国家和渠道。
- 渠道搜索使用轻量目录，250ms 防抖，忽略过期响应，失败可重试。目录读取设置 `apply: false`，不替换当前报价使用的完整价格规则。

## 本地验证

基于组合 SKU 发布候选 b95b3e9943f45f381536acb11d3fd652b4753dd9 的独立工作区验证：前端全量 1028 项通过、10 项按既有环境条件跳过。覆盖草稿保留/替换/版本号、当前采购价格、无权读取、请求失败、跨区域渠道、组合 SKU、非常用国家加载、跨国渠道检索、旧响应隔离、失效渠道移除和目录不污染当前运价。

发布准备采用独立分支 codex/quotation-reissue-search-20260922，保留 V46、顺友三个渠道、组合 SKU 数量显示、财务审核和新版报价同步逻辑。本次无后端及数据库迁移改动。发布时使用共享 flock 与期望生产 SHA 双重校验，按“提交并验证 GitHub SHA → 质量检查 → 备份 → 顺序切换 → 健康检查”执行；部署证据保存在统一 release-packages 版本目录。主目录另有既存修改，不在本次提交范围。
