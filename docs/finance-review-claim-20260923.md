# 财务审核领取占用

## 范围与基线

本地实现基于 `10a8eca6151abd80c95509d0a4f2b6c865b7204c`（本地发布证据对应 quotation-2026.09.23-15），独立分支 `codex/finance-review-claim-20260923`。财务单功能提交为 `d0e20e4c73c5d45e4311075973e49af832d53558`，随后在本工作区合并归档任务 `ddef21cd90573aa726aa8809751081c99d3954a5` 并补充联动。桌面主目录及其他任务工作区未被覆盖。本任务未部署、未操作生产业务数据。

最新基线已有财务待审／可报价／价格有误三个状态、审核历史和员工端轮询。本次在此基础上增加占用，保留既有结论及原报价确认、成交逻辑。

## 使用方式

- 列表显示待审、审核中（人名和开始时间）、审核结论；新增审核中和我正在审核筛选。
- 点击开始审核才占用，返回最新报价详情；普通查看不占用。
- 领取人可审核完成（可报价或价格有误），或取消审核。价格有误需要说明原因。
- 其他财务只能查看。超级管理员可填写原因解除他人占用，不能替他直接提交。
- 已完成的记录可显式重新审核，形成新的占用和审核记录。
- 不设置超时释放：关闭页面、断网、退出账号后保留占用；本人再次登录继续，无法继续时由超级管理员解除。
- 失去占用后旧页面、重复点击、旧版直接修改审核状态接口不能绕过校验。

## 数据和并发

新增 `quotation_review` 表（迁移暂定 **V50**），按报价 ID 唯一关联，记录状态、领取账号、独立审核版本以及审核人/时间/备注/历史。没有审核元数据的旧记录按待审读取；迁移只复制明确保存的 approved/rejected 结论，不推断成交或报价确认等于财务审核。

所有审核写入与原报价编辑统一先锁 `quotation_record` 行，再访问审核表。数据库事务串行检查领取资格；两个版本分别控制报价内容和审核占用。开始、完成需要报价内容版本匹配；取消、解除也必须匹配原审核占用版本。没有跨 HTTP 请求持续持有数据库锁。

领取、取消、完成、解除不会修改原报价 payload、业务 version、updatedAt、金额、成交结果或创建时间。审核状态由列表、详情、状态轮询统一覆盖旧 payload 字段；分页筛选在数据库执行，批量读取当前页审核数据，避免逐条查询。

## 联动规则

| 模块 | 行为 |
| --- | --- |
| 客户报价及数量列 | 实际报价单单元格变化后，审核中保留领取人但拒绝旧内容完成；已完成审核变回待审，留存原结果历史 |
| 客户名称 | 修改后同样需重新核对，避免审核对应错客户 |
| 普通备注、报价确认、成交状态 | 不重置财务审核；在审页面遇到报价业务版本变化仍要求重新载入最新详情 |
| 编辑器和轮询 | 轮询只更新状态，不悄悄更新正在核对的报价内容版本；原占用失效后不自动换用新占用版本提交 |
| 客户报价图片、复制、原CSV | 保持原字段和金额，内部审核信息不注入对客报价单；筛选导出与列表范围一致 |
| 总览统计 | 审核不改变金额、数量、转化率或业务待处理口径，也不更新“最后修改”时间；归档功能沿用其约定：归档计入经营统计、回收站排除 |
| 归档／回收站 | 使用权威审核状态保护记录，审核中或已有审核结论不可清理；归档/回收站记录不可开始审核或编辑。与审核争抢使用同一报价行锁；恢复不复活旧占用 |
| 再次发起 | 既有显式输入白名单不复制审核；服务端创建重置包括领取账号在内的全部审核字段 |
| 采购／物流／财务设置 | 不改计算和数据；历史快照不随当前参数变化重算或批量重置审核 |
| 员工权限 | 只读取自己报价的审核及历史，不获得审核权限；普通财务无管理员解除能力 |
| 培训系统 | 无代码、数据、配置或服务变更 |
