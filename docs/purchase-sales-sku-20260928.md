# 在售主 SKU 销量匹配

采购页提供简洁销量入口，明细独立打开。全部、待补资料、未匹配三个分类中，待补资料只包含已匹配的采购记录。支持采购报价人、缺失项目筛选、分组、按需显示月度列和 CSV 导出。

只用销量汇总表主 SKU 精确匹配采购 SKU；大小写与空白在准备来源文件时规范化，保留后缀。子 SKU 不替代主 SKU。固定期间销量不等于滚动90天，源表月度与汇总差异保留并提示。有效0%票点、0元运费与空值区分。

GET /api/v1/purchase-sales 需要采购权限，每次请求读取当前采购字段，没有业务写入。未配置销量来源时返回明确错误，不将缺失来源当作零销量。

## 私有来源部署

真实销量文件不得提交到代码仓库或打入公开前端资源。由受控发布流程将其放在服务器版本化的数据目录，保存源工作簿与 JSON 的 SHA256、数据核对和回退证据。

生产 .env 配置：

- QUOTATION_SALES_DATA_DIR：服务器上该版本销量 JSON 所在目录。
- QUOTATION_SALES_SOURCE：file:/app/purchase-sales/sales.json。

Compose 将目录只读挂载到 /app/purchase-sales。后端通过 APP_PURCHASE_SALES_SOURCE 加载，启动时验证非空、唯一主 SKU。每个发布版本固定数据目录并保留回滚文件；更换来源需要校验后重启后端。备份时另外复制私有来源及其校验文件，常规数据库与对象备份不包括该挂载目录。

测试使用合成来源。权限、真实 PostgreSQL 投影、主子 SKU 分离、零值、无写入、缺失筛选、窗口切换与月度列均有自动化覆盖。实际数据数量和生产验收结果保存在私有发布证据中。
