# 按渠道、国家与重量段执行计费进位

线上原先只有科威特云途化妆品、1g专用模型及0.5kg整票价执行进位。普通公斤价中的进位字段及多份原表的国家级进位说明没有参与计费。本次统一按“最低计费重补重 → 对应进位规则向上取整 → 匹配运价档位 → 公斤价加每票费”计算，前端使用decimal.js，后端使用BigDecimal。

## 已核对的范围

基于2026-09-23生产生效库113渠道、4223价格段，19渠道435价格段具备明确进位规则，其中包含此前已上线的科威特1段；本次新增执行434段。数量是价格段数，不是历史订单数量。

| 物流商 | 价格段 | 依据 |
|---|---:|---|
| 云途 | 105 | 原表进位列：特惠普货41、特惠带电41、化妆品12、服装11 |
| 云速递 | 60 | 普货/带电各6段配置0.1kg；敏感48段，2026.9.21原表A56以g进位 |
| 闪电猴 | 24 | 美国6渠道各4段，已配置0.001kg |
| 递四方 | 115 | 20260909原表OH A61、QC A82为全表g进位；特殊国家条款独立限定国家 |
| 万邦 | 1 | 化妆品日本，原表B55日本段落0.5kg |
| 通邮 | 3 | 纯电池韩国L36按1kg；特货智利I96:I97超过2kg按0.5kg |
| 顺丰CD | 127 | 用户提供的20260916原表B162:C179及用户确认 |

原表通邮纯电池L18的500g进位属于日本，不能套用到其他国家；该库无日本相应价格行。万邦多渠道复制的日本备注也不能套用到其他国家。

顺丰CD按国家区分：

- 加拿大、美国、英国、法国、德国、墨西哥、瑞士、澳大利亚、新西兰及B168列明的欧洲国家：1g。
- 沙特、阿联酋、泰国等原表明确国家：0.1kg；日本0.5kg（本库无该国CD有效行）。
- 尼日利亚、乌干达、肯尼亚、加纳：≤2kg按0.01kg，>2至10kg按0.5kg，>10kg按1kg。
- B179列明的国家：0.01kg，对应本库重量上限2kg。
- 意大利、保加利亚、罗马尼亚、爱沙尼亚、拉脱维亚、克罗地亚、坦桑尼亚未出现在该说明中，按用户2026-09-23明确确认的1g处理。

## 数据及模块边界

- V48只重建生成的报价读取列，不更新原始payload、运费、挂号费、最低重量、价格指纹、审核记录或历史报价。
- 财务系数、汇率、税费、客户操作费、美元报价最终取整逻辑均不改动。因国际运费正确进位，新计算的总报价会随运费变化。
- 采购产品重量、历史报价和已存草稿金额不批量重算。刷新页面后使用新规则，报价提交仍由服务器复算校验。
- 对无进位配置且无明确原表依据的渠道，保留现有规则；原1g和500g专用模型保留。
- 规则使用文件供应商、来源表、国家与原说明匹配，避免把整表复制的备注误当全局规则。明确数值进位优先于备注推导。
- 计费引擎升至v9，报价manifest与浏览器缓存版本同步更新，避免旧页面数据漏掉分段规则。
- 保持已有Excel列位置，末尾新增可选“分段进位KG”列，例如`0以上:0;2以上:0.5`。标准价格导出再导入时保留分段进位及原价格。

## 验证

- 从原始行和独立Python Decimal计算构建622条回归价格行、10114组计重/金额样例，包含所有435条明确规则及其他渠道反例；前后端分别与预期比较。
- 覆盖最低计费重、小数克、刚好整单位、刚超过单位、2kg/10kg分界、跨价格段、上限外不可报价、不同国家及分区。
- PostgreSQL从47升级48，核对报价读取字段、Java/SQL备注适配一致、原payload与价格指纹不变、原审批保留、新v9审批可用。
- Excel实际导出/重新解析后核对分段规则及运费，并执行后端试算。
- 生产发布与发布前后数据对照结果单独记录在对应发布包；本说明本身不代表部署完成。
