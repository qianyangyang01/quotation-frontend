# 欧盟关税叠加成员国处理费

## 操作方式

财务 → 渠道税费设置 → 罗马尼亚 → 本国计费方式选择“欧盟关税＋本国处理费”。选择物流商和渠道，编辑或批量填写处理费，核对后保存并发布。

例如欧盟对应渠道关税为 $3/单，罗马尼亚处理费为 $1/单，报价计入 $4/单。购买 1、2、3、10 件，固定处理费均只收 $1。页面列出欧盟关税、处理费和合计；报价税费标签也展示拆分。

- 本模式适用于系统成员国资源中的欧盟国家，支持中文、英文及国家代码匹配。
- 只有明确切换的国家启用叠加模式。原“单独国家关税（覆盖欧盟）”和已有规则保持不变，可切回使用。
- 本国处理费单独存储，不把原本国关税自动转换为处理费。未填写的渠道不加处理费；编辑新费用时金额为空，必须填写金额或选择不加处理费。
- 欧盟已含税或无关税时，处理费仍可收取；本国不加处理费时，欧盟关税仍保留。
- 欧盟或本国渠道不支持、欧盟组未启用、所需汇率缺失等情况阻断报价。
- 云途 CHC 原欧元重量公式保持有效，并叠加独立处理费。重量沿用现有报价传入的整单税费重量；未修改物流最低计费重或实际重量逻辑。
- 现有“附加费”仍独立计入。同一处理费如果已经在附加费设置维护，使用新入口前应移除重复项；本次不自动搬迁或删除任何费用。

## 实现与数据边界

财务 tax-settings 的成员国行新增可选 `euTaxMode` 与 `handlingRules`。未切换的旧记录沿用原行为；无需数据库迁移。附加费规范化不带入新模式字段。

前端计算拆分欧盟关税与本国处理费，使用十进制运算及既有最终报价舍入规则。新报价 `eu-handling-v1` 快照记录两项金额、合计、渠道、国家和整单重量。

后端正式保存入口调用独立核算，检查欧盟规则、处理费、汇率、数量档金额及重量样本。配置变化或切回旧模式后，旧叠加报价需重新计价再提交。既有财务权限、版本冲突保护、审计和 JSON 保存路径不变。

没有批量改写历史报价、采购、物流价格或生产设置。首次本地验证未写入任何实际处理费金额。发布仅交付功能，保留既有实际财务配置。
