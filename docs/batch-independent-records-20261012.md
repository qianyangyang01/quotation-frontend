# 批量报价按 SKU 独立保存

## 业务行为

- 普通单品批量、FOB 批量一次提交，每个 SKU 生成一条原有 `quotation_record`。
- 每条使用原有报价单号、权限、审核领取/通过/退回、审核历史、成交跟进。没有新的批次审核状态机。
- 同一 FOB SKU 的多个指定数量保存在一条 schema-1 单品快照中；各数量的实际价格完整保留，再次发起也保留数量清单。
- 批次号由服务器生成，记录中可点击/搜索同批报价；批量页面保存成功后可直接进入本批记录。
- 合并客户报价单的预览和图片导出继续保留。新记录的日常审核使用原列表和详情。
- 标题中央的“批量单品报价记录”按钮移除；旧数据仍可经低优先级“历史批量记录”入口查看和按旧流程处理。

## 保存与历史保护

`POST /api/v1/quotations/batch` 校验完整合并快照，再调用与普通保存共用的记录写入逻辑。整批在一个事务中写入，失败全部回滚。使用账号锁与整个请求的幂等键处理重试和并发提交。响应只包含批次及独立记录索引，不产生额外待审核汇总记录。

普通报价保留采购、物流、客户价格和报价单布局快照；FOB 每条保持 schema 1 及原采购来源。重复 SKU 的 FOB 数量合并不使用旧 schema-2 批量审核。单条撤回取消后，原批次请求不能重放生成副本。

无数据库迁移，不批量改写既有单品、FOB 或历史批次，也不重算历史价格或重置历史审核、成交状态。旧批次接口保留以便读取和处理历史数据。
