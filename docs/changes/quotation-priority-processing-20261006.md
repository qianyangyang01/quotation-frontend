# 报价优先处理

## 用户入口

- 我的报价：保存报价旁增加“优先处理”勾选项，默认不勾选，不填写加急原因。
- 我的报价记录：本人待审核或审核中的当前记录可“设为优先 / 取消优先”。优先记录显示橙色标签和浅色背景。
- 我的报价记录和公司报价记录均支持“只看优先”；优先记录在前，优先记录内部按创建时间从早到晚，普通记录保留原来的创建时间倒序。

## 联动规则

- 权限由后端校验，其他报价员、财务和管理员均不能替本人改变优先标记。审核人员仍按已有权限领取、审核和写意见。
- 标记存放在独立的 quotation_review 状态中，与报价价格快照分开。设置、取消不会更新报价金额、创建时间、更新时间、报价版本、成交状态或审核领取人。
- 使用报价行锁及报价、审核两个版本号处理并发；页面在失败时显示错误并刷新权威审核状态，不提前改标记。
- 所有审核结论（审核通过、价格异常、同渠道免审）均结束本次优先状态。重新领取已完成记录不会恢复旧标记。
- 撤回、归档、移入回收站结束优先状态；恢复记录不会恢复旧标记。取消报价沿用原取消流程。
- 撤回重新编辑支持保存新的勾选状态；重新提交按本次显式选择设置。再次发起默认不继承原记录优先状态，新建报价默认普通。
- 标记变化进入审核历史和操作审计，不计入审核意见数量，不替代审核完成通知。
- 筛选、排序在服务端分页之前完成，统计与导出使用同一筛选条件。导出增加“优先处理”列。
- 页面沿用审核状态同步，并刷新当前记录列表，使空队列和其他分页新增优先记录可进入当前结果。
- 复用现有审核状态 JSON，无新增数据库迁移，不批量修改历史报价。
