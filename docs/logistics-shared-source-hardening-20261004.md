# 物流原表共用解析增强

多家物流商共用的表格解析此前直接提取时效栏中的前两个数字，可能把日期、小时或多组时效误作天数；说明区分隔和产品号别名支持也不一致。

本次在共用流程识别产品代码、产品编号和产品号，云途标题支持同格及相邻单元格写法，仍拒绝缺失或冲突的代码。说明区仅由首个有内容单元格中的明确标题启动，避免价格行备注中的“客户须知”等文字截断价格；纵表与巧捷整票表遇到有效价格表头恢复解析，顺友保留限重档位连续性。通邮横表在已知说明区停止，保留原始证据。

时效整格识别明确的天数或范围，兼容工作日、自然日、单天数、不同连接符及万邦双连字符。单元格未标单位时要求表头明确天数单位。日期、小时、倒序、零值或多组承诺保留原文与位置，提示核对，不猜测天数，也不以其他重量段、页尾或旧版人工时效掩盖新表异常。用户本次明确补正仍有效。时效为可选资料，不影响已验证价格的发布；价格、重量、产品身份、计费模型和发布基线校验继续有效。

新解析器 `shared-source-layout-2026.10.04-v2` 明确纳入版本兼容清单，保留已验证旧版的发布兼容性和原始版本审计。规则作用于以后导入，不改写现有正式价格、草稿、历史报价或审核状态。

回归包括跨物流商表头别名、说明区邮编、后续表头、价格行内备注、时效误读及继承、云途代码冲突、顺友限重和巧捷整票价。可通过既有原表语料测试校验 11 份原表移行后的价格一致性，并在隔离 PostgreSQL 中重放这次的 12 份旧稿发布。
