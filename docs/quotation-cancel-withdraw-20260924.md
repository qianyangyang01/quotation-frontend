# 报价永久取消与撤回重新编辑

## 范围与行为

本人当前、未成交且无成交明细/数量的报价新增「取消」「撤回重新编辑」，保留「再次发起」。审核中、审核通过和价格异常均可操作；归档与回收站仍走原流程。

- 取消经确认后物理删除报价、审核、物流历史快照及原报价审计正文；仅留下取消操作的单号、操作者、时间等最小日志。已缓存的创建/重新提交响应清空并保留 410 防重标记。
- 撤回保留原记录，内部状态为 `withdrawn`，退出业务列表、审核队列和分析统计；本人已有任何草稿时拒绝撤回。
- 服务端保存草稿的原单关联与原单版本。进入报价页恢复原条件，按当前采购、财务、物流资料计价；重新提交更新同一 ID/单号，保留归属和创建时间，保存修改前后快照，重置处理、报价确认和审核结论。
- 撤回草稿的清空操作明确标为「放弃编辑并取消报价」，确认后删除原单及草稿。普通草稿覆盖、旧接口、新建报价和再次发起不能越过此关联保护。

## 事务及接口

V52 扩展生命周期约束，并给 `quotation_draft` 增加 `source_quote_id` 外键、唯一索引及 `source_quote_version`。不改历史报价数据。

三个 POST 接口为 `/api/v1/quotations/{id}/withdraw`、`cancel`、`resubmit`，均要求 `Idempotency-Key` 与 `_version`；关联草稿提交/取消另要求 `draftVersion`。撤回传递可编辑条件 `draft`，重新提交传递完整 `quotation`。新重新提交接口强制要求采购、财务版本，不能利用旧创建接口兼容无版本客户端的路径跳过核验。

涉及草稿的写操作按账户行、幂等锁、报价行、审核行的顺序串行化。账户行锁覆盖草稿尚不存在时的竞争；审核、改价、确认、成交继续共用报价行锁。身份、权限、成交保护、原单版本和草稿版本在服务端再次校验。每次撤回/取消/重新提交的业务写入、审核变更、草稿变更及幂等响应共同提交或回滚。

审核先完成时，报价未成交仍可撤回/取消；报价内容先修改时旧版本操作拒绝，刷新后才可再操作；成交先完成时始终拒绝。撤回/取消先完成时旧审核、改价、确认和成交请求拒绝。成功状态同步检测到撤回/消失后关闭旧窗口；同步失败保留错误提示，不推断删除；迟到响应不能重新激活失效窗口。
