# 模板保存复用旧清单修复

chenchen 的生产模板“带电”“普货”“化妆品”在 2026-09-24 新建时均保存了相同的 5 条渠道；三个版本号均为 0，审计记录均为 create，没有后续 update。只读核验了模板和草稿，没有修改业务数据。

具体操作顺序无法从现有记录确认。代码及草稿显示两条需要修复的路径：

- 三种报价模式独立保存选择。指定模式的草稿存在另一份 4 条渠道清单，但原模板管理按钮始终从模板模式取清单，不能直接保存其他模式刚选好的渠道。
- 应用新模板期间仍允许保存旧清单。已用同一回归用例验证：生产基线代码的保存按钮仍可点击，修复后在加载和失败状态下均禁用。

修复增加常用/指定模式的“将当前清单存为模板”入口，将明确选中的清单复制到模板工作台；管理界面展示来源及即将保存的国家、渠道、区域明细。保存期间防止重复提交，并且保存响应不会重新应用旧快照覆盖后续编辑。失败会显示错误并保留输入。

模板内容和渠道定价逻辑保持原有格式。已有错误模板没有自动更改：现有证据不足以确认两个模板原本的完整选择，不能根据名称猜测或从当前指定模式草稿直接覆盖。

验证：5 个测试文件 47 项通过，包括连续保存三个独立模板、直接增删模板渠道、重新加载、两个真实页面入口、加载失败防旧数据提交、保存期间继续编辑。TypeScript、相关 ESLint、生产构建通过。本地浏览器检查来源与明细布局，并验证新建化妆品模板与原带电模板独立。

发布范围为前端；不修改后端、解析器、数据库、已有模板或培训系统。发布前检查当前生产 SHA，保留并发发布的变更；正式切换前进行新的完整备份并校验，回滚只恢复之前前端镜像。
