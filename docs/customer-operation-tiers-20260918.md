# 客户操作费四档

- 财务每客户维护 1、2、3、3以上四档 USD/单。单品按件，组合按套数；每个数量列按档加一次，不乘件数或组合内商品数。
- 费用位于税费/附加费之后、佣金阈值之前，继续使用十进制工具和原有 0.05 美元向上取整。
- 原有 finance-settings API、权限和 JSON 存储不变。配置及报价 customerOperation 增加 feesByQuantityUsd（1、2、3、above3），保留 feeUsd 为第一档兼容字段。
- 旧配置只有 feeUsd 时四档等值；新建客户四档默认 0。存在四档但缺值/无效不能静默回退。金额范围 0–1000000，最多两位小数。
- 旧客户端提交单档快照时仅在当前四档等值且金额匹配时允许保存；不同档位返回 409。旧财务客户端不能将现有四档覆盖成不匹配的单档。
- 草稿仍按账号保存客户选择；恢复时读取当前配置。页面通过既有版本同步提示更新报价，保存前再次校验，服务端在原事务中锁定财务版本与快照。
- 新记录保存四档快照。历史记录金额、固定费用保持原样；内部详情和对账复制使用记录快照展示每数量档费用，客户报价图片不展示费用明细。
- 无数据库迁移、历史回填或生产费用修改。部署后由财务自行填写所需金额。

## 验证

- 0.30/0.50/0.70/0.80 覆盖 1、2、3、4、5、10 件及套数；税费、附加费、佣金1/0.95、动态价格列、重复计算及复制。
- 草稿恢复已选客户、旧金额兼容、非法输入、四档缺值、配置变化、快照深拷贝、记录对账。
- 真实 Spring Security 测试：员工只读，管理员/财务写入，旧版本409；8个并发保存1成功、7冲突，员工读取胜出完整配置。
- 本地测试数据库用于写入和并发验证。生产验收只读，不新增正式报价或客户配置。

## 发布注意

在生产无进行中物流导入时发布；保存完整备份和 current/previous。对比既有报价价格/重量及财务配置哈希。
尚未配置不同四档前可回退前一版本；一旦财务配置了不同四档，不应直接回退到只识别单档的旧代码，应优先向前修复，保留快照数据。
