# 模板加载失败专项排查

基线为生产 `quotation-2026.10.04-06` / `ea098c1`。

生产只读结构检查：128 个模板、25 个所有者；无缺失名称或非数组渠道列表。现存后端日志的两条 ERROR 为输出连接 Broken pipe，不能证明用户此前的具体失败原因；未取得具体账号、模板和发生时间，历史个案原因仍不可追溯确认。

通过延迟响应和失败注入复现以下问题并修复：

- 模板列表读取失败抛出未处理异常，页面无重试入口。增加持续错误提示、加载状态和显式重试；刷新失败保留已有模板。
- 切换账号/并发刷新后，旧列表响应可覆盖新列表。使用请求序号拒绝旧响应，账号切换时清除旧账号列表，卸载时作废请求。
- 应用模板时商品查询尚未完成，会立即失败；已开始的模板国家请求被新商品查询取消后仍可能留下错误。等待来源就绪，再继续尚未完成的应用；忽略被取代请求的返回。已成功应用的模板不因重新查询而重放，保留临时删改。
- 加载原因被统一吞成“模板渠道加载失败”，现在展示实际商品/物流错误并提供“重试加载模板渠道”。失败不清空已保存模板。
- 新模板加载失败时，旧预览清单可能保留。模板加载状态现在联动报价保存按钮和提交前后校验，阻止将旧清单按新模板身份保存。

新增回归覆盖列表失败恢复、账号切换晚响应、商品查询等待、查询替换后晚失败、真实错误与手动重试、临时删除不回填、失败/加载时阻止保存且不阻挡快速模式。执行模板专项、草稿初始化、再次发起、全量前端、ESLint、类型检查、构建及隔离校验。

仅前端发布；不改后端、模板数据、报价历史、审核或成交状态。生产验收仅查询、应用和清空临时清单；不保存模板或测试报价。发布包与备份/回滚/数据指纹证据存于 `release-packages/quotation-2026.10.04-07`。
