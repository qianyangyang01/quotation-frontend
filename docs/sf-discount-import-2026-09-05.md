## 计价优先级与异常

1. 顺丰有“折后运费”“结算运费”或“SF折后”列时，使用该列的可靠数值，不再乘折扣。该列为空、零、负数、文本错误或不可靠公式时阻断，不回退原价。
2. 没有折后列而有“折扣”“折扣率”时，原每公斤价格乘折扣。支持0<系数<=1、明确百分比以及“7折”等数字折扣；空白、零、负值、裸7/70、大于1、模糊文字和错误公式阻断。
3. 原价和折后价均按Excel实际数值读取，保留精度，继续由现有计费引擎在运费合计时舍入。Excel显示112.2但实际存储112.24的行采用112.24。
4. 没有折扣相关列时保留原价逻辑。操作费仍单独每票叠加，不随运费折扣变化。
5. 重复折后/折扣列视为歧义；不可靠关键金额使行不可报价。公式仅读取可靠缓存，不执行宏、不访问外部引用。
6. 保留原价、折扣、折后价、源单元格和实际选择依据，便于对照原始Excel。行数、重量段、区域、时效、附加费及既有待适配阻断继续由原规则处理。

## 测试设计

- 法国97→51且折扣1.0；意大利98/0.7/70.6优先70.6；德国71/0.64/45.44只采用一次45.44。
- 单独折扣的数值、百分比文本、Excel百分比格式、数字几折；1.0不折扣。
- 空/零/负/错误折后价；错误折扣；错误公式、可靠缓存公式；折后列存在但原价列缺失；合并折扣单元格；重复折后列。
- 相同表头对其他9家物流商仍取原价97。
- 使用通用计费引擎核对法国0.3kg：51×0.3+20=35.30，操作费不折扣。
- 本地真实顺丰工作簿逐行核对实际单元格值；11份历史物流工作簿核对人工样例和业务基线。另以生产16版直接解析结果逐字段对照，只允许顺丰单价及对应哈希、来源证据、解析器版本变化。
- 全后端测试验证导入、报价、权限、存储等已有路径。测试用例和证据不写入生产。
