# 首选渠道空状态同步修复

初始物流加载未找到可用渠道后，模板或附加国家稍后可能加载出正常报价，但首选状态仍为空，导致保存提示“请完成物流试算并设置一条首选报价渠道”。

报价工作台在当前清单加载完成且数据核验通过后，仅补齐空缺的首选，按清单顺序选择首条能按当前主报价数量计价、税费完整且具有有效渠道标识的渠道。已有首选保持不变，使用当前数量的实际运费，组合模式按一套核算。后台恢复的原渠道失效时仍保留人工确认要求，不自动替换。

同步仅更新当前页面中的报价状态。未改动报价记录、采购、物流、计费引擎、保存接口或数据库迁移；不会自动保存、重算或覆盖历史报价与审核状态。

验证：

- 新增响应式回归测试覆盖延迟加载、切换清单、人工首选保留、失效历史渠道、税费/权限/数量检查及加载/恢复/同步期间阻断。
- 完整前端测试：319 个测试文件通过，2776 项通过；19 个测试文件和24项原有可选测试跳过。
- TypeScript 检查、ESLint、正式前端构建通过。
- `scripts/qa/primary-channel-sync-browser.mjs` 使用隔离 API 与模拟运价，验证 TC2602577 模板从无首选到自动补齐、人工改选保留、显式保存后唯一首选与记录汇总一致；无历史记录/模板/草稿修改请求。
