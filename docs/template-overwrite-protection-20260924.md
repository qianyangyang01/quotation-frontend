# 报价模板覆盖保护

模板列表刷新曾将编辑器使用的版本号替换为最新版本，而临时渠道清单仍来自旧版本，导致旧清单通过版本校验覆盖另一页面的新配置。选择下拉框与已应用模板也可能不一致，更新按钮没有明确显示目标。

现在将已应用渠道与模板 ID、初始版本、保存内容绑定。复制等列表刷新不会更新该编辑基线；发现不同版本、下拉选择与应用目标不同，或从不含模板版本的草稿恢复时，禁止覆盖并提示重新应用。另存为新模板仍可保留临时清单。主动重命名成功时，仅在原编辑基线版本一致的情况下推进基线。

点击更新只打开确认窗口，显示目标名称、移除与新增的国家/区域/渠道；确认时使用固定快照和初始版本。目标或清单变化会使确认失效。成功后推进编辑基线，不重复提交。

后端渠道更新必须携带匹配模板 ID 和版本的确认信息，拒绝旧页面绕过新版交互；并继续使用 JPA 乐观锁防止并发覆盖。仅允许修改 name、description、items，不持久化请求控制字段。每次更新审计保存前后名称、说明、渠道、版本及操作来源。无需数据库迁移，不重算或修改已保存报价。

验证包括列表刷新后的旧清单覆盖、下拉目标不一致、确认前后并发修改、取消、重复点击、连续编辑、草稿恢复和原有模板选择/不可用渠道回归。后端验证旧协议、错误确认目标/版本/来源、空渠道、重复旧版本提交、审计前后快照与归属字段保护。桌面及 390px 宽度的确认窗口进行浏览器渲染检查。

升级后，尚未刷新的旧页面如尝试修改模板渠道会收到冲突提示，需要刷新并重新应用模板。模板正常应用与报价不受此协议变化影响。验收使用本地模拟数据及生产只读检查，不修改员工模板。
